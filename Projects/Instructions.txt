COMP 141 – Phase 2.1: Lexp Parser
Author: Channen hill

------------------------------------------------------------
Project Description
------------------------------------------------------------
This project implements a scanner and a recursive-descent parser
for the Lexp language, which is a subset of Limp. The program reads
a single Lexp expression from an input file, tokenizes it, parses it,
and produces an Abstract Syntax Tree (AST) in preorder format.

The output file contains two sections:
1. A list of tokens (one per line, showing value and type).
2. The abstract syntax tree (AST) printed in preorder with indentation.

------------------------------------------------------------
Files Included
------------------------------------------------------------
parser.py          – Main program containing both the scanner and parser.
test_input.txt     – Sample input file containing an Lexp expression.
test_output.txt    – Example output generated by the parser.
instructions.txt   – This file (build and run instructions).

------------------------------------------------------------
How to Run
------------------------------------------------------------
Requirements:
- Python 3.8 or newer (no additional libraries required).

Usage (from terminal or command prompt):

    python parser.py input.txt output.txt

Example:

    python parser.py test_input.txt test_output.txt

The program will:
- Read the input expression from "test_input.txt".
- Generate the list of tokens and the AST.
- Write all results to "test_output.txt".

------------------------------------------------------------
Error Handling
------------------------------------------------------------
If the scanner encounters an invalid token or unknown character,
the program will print a “SCANNER ERROR” message and stop.

If the parser encounters an invalid expression (missing parenthesis,
misplaced operator, etc.), it will print a “PARSER ERROR” message and stop.

------------------------------------------------------------
Notes
------------------------------------------------------------
- Whitespace between tokens is ignored.
- Parentheses do not appear in the AST.
- The AST is printed in preorder traversal with indentation showing depth.
- The program is tested and verified with the example expression:

    (3 + a * (b - 2 / (c + d * (e - 4))) - 5) * (x / (y - 7) + z * (1 + w))
